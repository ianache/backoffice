<task type="auto">
  <name>Task 1: Install federation plugin and update vite.config.ts</name>
  <files>portal/package.json, portal/vite.config.ts</files>
  <action>
Install the federation plugin as a devDependency inside the portal package:

```bash
cd portal && pnpm add -D @originjs/vite-plugin-federation@1.4.1
```

Then replace portal/vite.config.ts entirely with the federation-aware config. Key points:
- Use `defineConfig(({ mode }) => { ... })` factory form so `loadEnv()` can read VITE_REMOTE_* vars
- Import `federation` from `@originjs/vite-plugin-federation`
- Build the `remotes` object conditionally: `if (env.VITE_REMOTE_STUB) remotes['mui-stub'] = \`${env.VITE_REMOTE_STUB}/assets/remoteEntry.js\``
- Keep existing vue() plugin call with `isCustomElement` for `md-` tags — do NOT remove it
- Add `federation({ name: 'shell', remotes, shared: { vue: { singleton: true, requiredVersion: false }, pinia: { singleton: true, requiredVersion: false }, 'vue-router': { singleton: true, requiredVersion: false }, axios: { singleton: true, requiredVersion: false } } })`
- In build options: keep `target: 'esnext'`, add `minify: false`, add `cssCodeSplit: false` — these are all required by federation
- Do NOT add `manualChunks` — breaks federation init order (see RESEARCH.md pitfall 6)
- Keep server `port: 5173, strictPort: true`
  </action>

  </verify>
  <done>portal/package.json lists @originjs/vite-plugin-federation@1.4.1 in devDependencies; portal/vite.config.ts contains federation() with name:'shell' and shared singletons for vue/pinia/vue-router/axios</done>
</task>
