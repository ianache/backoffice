The products endpoints on the backend are at /api/v1/products/* (Phase 7 built these: GET/POST /api/v1/products, PATCH /api/v1/products/{id}, and subscription endpoints at /api/v1/products/{id}/subscriptions).

Role requirements per ROADMAP/Phase 7:

Since the BFF middleware uses requireRole which checks a single role and the backend also enforces roles via X-User-Roles header, use requireAuth only (no role restriction at BFF level for products — the backend enforces role-specific access per endpoint). This mirrors the pattern in bff/src/routes/flags.ts which uses multi-role access.

Remove the deferred comment (lines 7-8 about WebSocket being deferred to Phase 10) and replace the entire sdkRouter.use() call with:
```typescript
sdkRouter.use(
  createProxyMiddleware({
    target: config.backendUrl,
    changeOrigin: true,
    ws: true,
    // Express strips '/sdk' prefix. HTTP SDK calls rewrite to /api/v1/sdk.
    // WebSocket connections to /sdk/ws/flags/:tenant_id rewrite to /ws/flags/:tenant_id on backend.
    pathRewrite: (path) => {
      if (path.startsWith('/ws/')) return path  // WS paths: /sdk/ws/... -> /ws/...
      return `/api/v1/sdk${path}`               // HTTP paths: /sdk/... -> /api/v1/sdk/...
    },
  })
)
```

Note: The backend WebSocket endpoint is at /ws/flags/{tenant_id} (not /api/v1/ws/...). The BFF mounts sdkRouter at /sdk, so a client connecting to BFF at /sdk/ws/flags/123 will have the /sdk prefix stripped by Express, leaving /ws/flags/123, which the pathRewrite returns as-is.
