<!-- vitest test pattern from portal (vitest@^1.6.0, see portal/package.json) -->

The composable is a module-scoped singleton. Tests need to reset state between runs. Options:
- Use `vi.resetModules()` + dynamic import to get a fresh module per test
- Or expose an internal `_reset()` for testing (cleaner)

Since the composable uses module-scoped `ref()` and `let client`, the cleanest approach is `vi.resetModules()` with dynamic import.

Mock strategy:
- Mock `@backoffice/sdk-js` entirely with `vi.mock()`
- Control `FeatureFlagClient.prototype.initialize` and `.evaluate` return values
- Test 1: Mock `initialize()` to reject → refs stay `true`
- Test 2: Mock `initialize()` to resolve, `evaluate()` returns specific values → refs reflect them
- Test 3: Call `init()` twice → `FeatureFlagClient` constructor called once only
</interfaces>
