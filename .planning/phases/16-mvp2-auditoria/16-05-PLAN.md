<objective>
Fix the blocking gap from 16-VERIFICATION.md: the frontend "View Diff" modal expects a NESTED response shape (`{id, action_type, target_type, target_id, diff: {added, removed, modified}}`) from `GET /bff/audit-logs/{id}/diff`, but the backend (correct, unit-tested, per the 16-01 plan) returns the FLAT shape `{id, added, removed, modified}`. This causes a runtime `TypeError: Cannot read properties of undefined (reading 'added')` when a user clicks "View Diff".

Also fix a secondary, non-blocking finding: `bff/src/routes/tenants.ts` does not forward `X-User-Email`, so `audit_logs.user_email` is blank for TENANT-target rows even though `tenants/router.py` (16-03) reads `x_user_email: str = Header(default='')`.

Purpose: Make the Diff Viewer actually work end-to-end (closes AUD-06's blocking gap and completes AUD-03's frontend consumption), and ensure tenant audit rows carry a populated `user_email` like other domains.

Output:
- `microuis/mui-tenants/src/services/audit.ts` — `AuditLogDiff` interface aligned to the real flat backend shape `{id, added, removed, modified}`.
